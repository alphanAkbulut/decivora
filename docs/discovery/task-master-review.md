## Patterns to avoid / limitations visible in code

1. **Zero versus missing:** legacy expand-task branches on truthiness of recommendedSubtasks at line193. Numeric0 reaches default count; explicit0 uses a different branch. The source shows this branch behavior; full command/model outcome was not reproduced. Before calling a splitter, distinguish missing/null/0 and return a stable no-op without model spend. This supports the earlier issue#1728 lesson; no claim that every current expansion route is broken.
2. **Configuration fallback widens tool surface:** selected MCP loader can fall back to all tools for invalid custom configuration/error. That can unexpectedly increase descriptors and context. Decivora should fail visibly or keep a validated minimal set; never widen capabilities after parse failure. This is a cost/surface concern, not a reproduced exploit.
3. **Parent Done cascades in the legacy updater:** setting top-level done/completed marks children done. Status edit is not evidence. Preserve Decivora's criterion-level verification and independent parent predicate; do not import this semantic behavior.
4. **Implicit highest reasoning:** inspected Codex provider chooses the model's highest supported effort when missing/unsupported effort. This can diverge from a cost-conscious caller's intent. Our selected profile must state explicit model/effort and reject unsupported values or request bounded review; do not silently upgrade.
5. **Prompt previews in logs:** legacy expansion writes previews of prompts to debug logging. For our private conversations, retain source IDs/hashes/length/error codes rather than raw excerpts in operational telemetry.
6. **Separate legacy/new status definitions:** blocked presentation in a newer formatter does not establish its acceptance in every validator. Export one tested mapping for UI/API/MCP and test unknown values without defaulting to To Do.
7. Task Master source inspected here does not establish our desired late-answer/decision-revision/AND-OR impact/actual artifact-evidence chain. This is a bounded absence of evidence, not a claim that the whole project has no memory/history/verification features.

## The subscription alternative: important feasibility correction

Task Master's Codex CLI path indicates that a separate paid API is not the only possible model transport. [Official OpenAI authentication documentation](https://learn.chatgpt.com/docs/auth) distinguishes ChatGPT subscription sign-in from API-key usage-based access and confirms CLI support. It also directs programmatic CLI workflows such as CI/CD to API-key authentication. Therefore do not treat unattended/background product service operation via subscription as supported merely because a competitor wrapper exists.

A **local, explicitly approved selected pilot** may be worth validating; public/multiuser service automation needs its own provider/usage eligibility. Our current API request/parser is not already attached to this transport. User authentication, model availability, quota, sandbox and output contract remain unverified. No token/monetary guarantee; no authentication file read or launch in this review. Our historic browser receiver contract failures remain failures and must not be relabeled passed.

Before any pilot: selected source-only synthetic request and exact schema; explicit model/effort; one approved call/retry policy; constrained working directory and tool access; timeout/process termination; original output and nullable usage; independent source binding/scorer; no canonical mutation. No account purchase is required simply to perform this source analysis.
